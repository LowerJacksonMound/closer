CodeRadar reads CLOSER's holes as first-class findings, on its own scan cadence. The flow (Ian, 2026-11-11): Cartouche first hands CLOSER's plan the hashed intent; without Cartouche, cl_plan goes yes/no until the person approves; then CLOSER writes, and the writing leaves holes as expected. CodeRadar's only job here is to scan the holes file at the same interval it scans everything else and rank them first. Repo: this directory (the CodeRadar tree, coderadar_mcp/). Stdlib only; change as little as the spec needs; the Builder, the mirrors and .coderadar/ are untouched.

Facts you work from (read them, do not re-derive):
- CLOSER's state dir for a repo is `judge.state_dir(repo)` in ~/Desktop/CLOSER/judge.py:47: ~/.closer/<repo.name>-<sha256(str(repo))[:8]>/ (CLOSER_HOME overrides ~/.closer). holes.jsonl there is JSON lines, one per hole: {"location": "file::name", "file", "function", "kind", "reasons": [str], "ts", optional "anchor"}. kinds: counterfeit, did not run, unchecked, unlandable. `holes.read_holes(state_dir)` in ~/Desktop/CLOSER/holes.py:123 reads it (tolerates a missing file).
- cr_infractions (coderadar_mcp/read_tools.py:1136) builds `records` from the mirror via _row_record (read_tools.py:916, the row shape every seat reads), ranks with _ranked (read_tools.py:1120: by `apply` tier yes, review, no; APPLY_STATES in tool_interface.py:73), pages with _pages_by_file. The target repo is `_target_dir()` (read_tools.py:778).
- cr_row (read_tools.py:1281) and every write tool resolve ids through write_tools._resolve_row (write_tools.py:237) -> _find_row (write_tools.py:177), which only sees mirror rows.

coderadar-mcp.sh
- Export PYTHONPATH with ~/Desktop/CLOSER appended after ROOT (a CLOSER_TREE variable at the top of the script, default ~/Desktop/CLOSER), so `import holes` and `import judge` resolve. Nothing in this tree defines a top-level holes.py or judge.py (checked). stdout stays silent.

coderadar_mcp/read_tools.py
- `hole_rows(holes, target)` -> list[dict]: one row per hole record, in the row shape of _row_record, pure (takes the already-read list; no disk). id `<file>::<function>::0`; file, function from the record; line 0, line_end 0; replace_span `<file>:L0-L0`; replace_span_live "", span_current false; finding_lines []; rule_ids ["CLOSER_HOLE"], rule_id "CLOSER_HOLE"; infraction = "CLOSER hole (<kind>): " + the reasons joined with "; "; solution_kind null; digest ""; has_solution false; status "open"; withheld false; species "closer_hole"; selected_role ""; apply "review"; apply_reason "no CodeRadar candidate: the repair is yours, filed with cr_submit"; withheld_by null; gate_withheld_reasons {}; variant = the kind. A record missing file or function is skipped. Two records on one location keep the latest (last in file order).
- `closer_holes(target)` -> list[dict]: the holes read by the gearbox on its cadence. The gearbox (system_scripts/gearbox.py:1762) already runs a manifest scan every MANIFEST_SCAN_INTERVAL_S (a duty row of the cadence table, base CADENCE_BASE_S 2.5 s = the dash slider's poll interval, poll_config.json interval_ms). On that same tick it also reads holes.read_holes(judge.state_dir(target)) and writes the list to system_scripts/closer_holes_<repo id>.json as {"target", "read_at", "holes": [...]} (one atomic write, the way the intent file is written; repo id from intent_file.repo_id). closer_holes(target) reads that file and answers its holes list, [] when the file is missing or names another target. No new interval, no new daemon, no read of ~/.closer from the MCP seat.
- cr_infractions: when withheld is not True, `records = hole_rows(closer_holes(_target_dir()), _target_dir()) + records` before filtering; file and rule filters apply to holes too. _ranked puts rule "CLOSER_HOLE" in a tier before "yes" (tier -1), so every hole page comes first; file grouping unchanged. The answer dict gains `"closer_holes": <count of hole rows before filtering>`.

coderadar_mcp/write_tools.py
- _find_row: after the mirror buckets, look through read_tools.hole_rows(read_tools.closer_holes(target)) and answer (row, "closer_holes") on an id match, so cr_row and cr_apply see a hole row (cr_apply answers kind "shape", diff null for one, as it does for a prescribed row). The id resolver's function-match step (`(file, function)` unique among live rows) counts hole rows as live rows.

Cartouche's release carries CLOSER's contracts, and ct_watch/ct_look read CLOSER's plan and holes back. Repo: this directory (the Cartouche tree, cartouche/). Stdlib only. Cartouche still never rewrites the spec or the release, never starts CLOSER, never talks to it: every new thing here is a read of a file CLOSER already writes.

Facts (read them):
- `release()` in cartouche/build_release.py:16 returns the release dict (released, domain_id, cartouche_sha256, clips, ...); `cmd_release` in cartouche/cli.py:135 writes it. cartouche_sha256 is a sha over the whole canonical spec (cartouche_compiler.py:96).
- CLOSER's plan hash in ~/Desktop/CLOSER/closer_mcp.py:143: rec = {"intent", "expectation", "contracts": [contract dicts in order]}; sha256 of json.dumps(rec, sort_keys=True). A contract is {file, name, params: [names], checks: [...], kind: "def"|"class"} (judge.check_contracts, judge.py:195, normalises kind to "def" when absent). plans.jsonl in the repo's state dir (judge.state_dir, judge.py:47) holds every plan; the last record with "approved": true is the plan in force. holes.jsonl there holds the holes (read with holes.read_holes; after 2-cr_holes_land, holes.latest_holes drops repaired ones; use latest_holes if it exists, else read_holes).
- Watch (cartouche/mcp_tools.py:23): watch binds spec, release, target; look and stop call hold_tree (cartouche/hold.py:54) and shape the answer in _rows; issues are rows {file, function, lines, fault, detail, sign, directive, warrant_type} from issues_of (cartouche/project_symbol.py:75). Fault words: project_symbol.py:45-48.

cartouche-mcp.sh
- PYTHONPATH gains ~/Desktop/CLOSER after ROOT (CLOSER_TREE at the top, default ~/Desktop/CLOSER), the way coderadar-mcp.sh does it, so `import holes` and `import judge` resolve. If the import fails at runtime, Cartouche carries on with closer null (it is optional, never a crash).

cartouche/build_release.py
- The spec may carry `"closer": {"intent": str, "expectation": str, "contracts": [contract dicts]}`. `closer_lock(closer) -> dict | None`: None when the spec has none; otherwise the same dict with every contract normalised (kind "def" when absent) and "sha256" = CLOSER's plan hash computed exactly as closer_mcp.plan does (same rec keys, sort_keys, no spaces changed: json.dumps default separators). A contract missing file, name, params or checks raises ValueError naming its index.
- release() puts `"closer": closer_lock(spec_data.get("closer"))` in the release. A spec without it releases exactly as today.

cartouche/hold.py and cartouche/mcp_tools.py
- `closer_issues(release, target) -> list[dict]`: the issue rows CLOSER's files add. State dir = judge.state_dir(target if it is a directory else target.parent). If the release has no closer or the state dir does not exist: []. Else (a) the last approved plan in plans.jsonl whose contracts (normalised) differ from the release's contracts, or whose sha256 differs, gives one row fault "locked", detail "CONTRACTS", function None, directive "The approved CLOSER plan does not match the release's contracts: re-plan from the release." No approved plan yet is not a miss (no row). (b) each hole gives a row fault "missing", detail "HOLE(<kind>)", file and function from the record, lines None, directive = the hole's reasons joined with "; ".
- Watch._from_probe appends closer_issues to the scan's issues (sealed is false while any are open; waiting stays waiting); the answer gains "closer": {"sha256": the release's, "plan": the approved plan's sha or null, "holes": count} or null when the release carries none. ct_hold gets the same rows (it goes through _from_probe).
- summary_of names them in its one sentence when present ("…, 2 CLOSER holes").
- The ct_watch tool description in mcp_tools.py says: a release with closer contracts is checked against CLOSER's approved plan and its holes; the agent sends the release's contracts to cl_plan verbatim.
